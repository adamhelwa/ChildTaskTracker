01 The problem

Sticker charts don't scale to two parents and a wide age range.

Most families track chores with a whiteboard or an app that stops working the moment a second parent, a teenager, or a real reward system gets involved.

👀

No shared visibility

One parent logs it, the other is out of the loop — no easy way for both to see and approve.

🎂

One-size-fits-all

The same sticker chart doesn't motivate a 7-year-old and a 15-year-old equally.

🎁

Rewards feel arbitrary

No system connecting effort to reward — it's negotiated fresh, every single time.

02 The solution

One loop: a kid marks it done, a parent confirms it, points do the rest.

ChildTaskTracker turns chores into a shared, validated, rewarding routine — without becoming another thing parents have to administer by hand.

→
🔔 Both parents notified

✅ Parent validates

03 From the PRD

Scoped deliberately: one family, real validation, AI as a helper — never the decision-maker.

👨‍👩‍👧 Who it's for

  • Co-parents sharing validation duties
  • Kids ages 6–16, with age-adaptive tone
  • Single-family tool first — built to generalize later

🛡️ Non-negotiables

  • AI recommends only from the parent's own reward list
  • Every AI feature has a deterministic fallback
  • 24h auto-approval, one-day streak forgiveness

06 Architecture

Everything lives in the browser. One optional call ever leaves it.

Hosting
GitHub Pages, static files
State
One JS object + localStorage
UI
Vanilla JS, hash router, no build step
Optional
Direct OpenAI call, key stays local

Every AI feature — reward suggestions, weekly recaps, starter tasks — has a rule-based fallback. No key, no network, no problem: the app behaves identically either way.

08 Key takeaways

What building this actually taught us.

🐛
One line broke every modal button
An event.stopPropagation() silently killed every Save/Send button — caught only by live-clicking the deployed app, not by reading the code.
📡
CDNs hide your own fixes
GitHub Pages' edge cache kept serving old JS after a push — versioned URLs (app.js?v=4) made re-verification trustworthy.
🛟
Fallback-first beats AI-only
Every AI feature ships a rule-based twin — doubles the code, but the product never breaks when a key is missing or the API is down.
⚖️
The real tradeoff: no backend, no sync
Zero infrastructure was the right call for an MVP demo — but it means no real cross-device sync until a backend is added.
