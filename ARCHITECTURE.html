Tradeoffs, insights, and risk management

The decisions the three figures above are actually making, and why.

⚖️

Design tradeoffs

No backend, no cross-device sync

Static hosting means zero infrastructure and "the HTML is the deploy," but each browser's localStorage is its own island — a parent's phone and a child's tablet don't sync. Two-parent sharing is a view switcher, not real accounts.

Client calls OpenAI directly

No proxy to hide or rate-limit the key server-side — traded for matching the "no backend" brief exactly, and for keeping every user's key local to their own browser, never in the repo.

Vanilla JS over a framework

No component diffing — the view re-renders from an HTML template string on every change. Traded for zero build step: the four files in the repo are the entire deployable artifact.

Fallback as a first-class feature

Every AI-backed feature ships two implementations, model and rule-based, doubling the code per feature so the product behaves identically with or without a key.

💡

Technical insights

One stopPropagation broke every modal

Delegating all clicks to a single document listener means anything that stops a click from bubbling silently disables the app below that point — only live click-testing caught it, not reading the code.

Hash routing vs. headless navigation

The router relies on real location.hash assignment, which fires hashchange; a testing tool's pushState-style navigation doesn't, and looked like a bug in the app when it wasn't.

The CDN hides your own fixes

GitHub Pages' edge cache served stale JS after a push even once the origin was confirmed correct; versioned query strings made re-verification deterministic.

Escaping has to cover AI output too

An OpenAI-suggested emoji or title is exactly as untrusted as anything a user typed — both land in the same innerHTML template.

🛡️

Risk management

Data loss

A family's entire history lives in one browser with no backup. Mitigated with an explicit, confirmed "Reset demo data" action rather than a silent clear, and documented as a known limitation.

API key exposure

The key never leaves the browser it was entered in and is never written to a file this repo publishes — cloning the repo can never leak a key.

Unsafe AI output reaching a child

Reward suggestions are constrained to the parent's own catalog by prompt design, money/screen-time are explicitly disallowed, and every call falls back to the same result shape so a bad response never surfaces as broken UI.

XSS from user or AI text

One esc() helper escapes every dynamic string before it's templated into the DOM, applied uniformly to human-entered and AI-generated strings alike.
